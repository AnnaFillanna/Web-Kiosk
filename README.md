## Данные

В приложении используются две основные сущности данных: товар и покупатель.

### IProduct

Интерфейс `IProduct` описывает товар, доступный в интернет-магазине.

```ts
interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}
```

Поля интерфейса:

- `id: string` — уникальный идентификатор товара.
- `description: string` — описание товара.
- `image: string` — путь к изображению товара.
- `title: string` — название товара.
- `category: string` — категория товара.
- `price: number | null` — цена товара. Значение может быть `null`, если у товара нет цены.

### IBuyer

Интерфейс `IBuyer` описывает данные, которые покупатель предоставляет при оформлении заказа.

```ts
interface IBuyer {
  payment: TPayment;
  email: string;
  phone: string;
  address: string;
}
```

Поля интерфейса:

- `payment: TPayment` — выбранный способ оплаты.
- `email: string` — электронная почта покупателя.
- `phone: string` — номер телефона покупателя.
- `address: string` — адрес доставки.

`TPayment` описывает доступные в приложении способы оплаты. До выбора способа оплаты значение равно пустой строке `''`.

### IProductsResponse

Интерфейс `IProductsResponse` описывает ответ сервера при получении каталога товаров.

```ts
interface IProductsResponse {
  total: number;
  items: IProduct[];
}
```

Поля интерфейса:

- `total: number` — общее количество товаров.
- `items: IProduct[]` — массив товаров, полученных с сервера.

### IOrder

Интерфейс `IOrder` описывает данные заказа, отправляемые на сервер.

```ts
interface IOrder {
  payment: TPayment;
  email: string;
  phone: string;
  address: string;
  total: number;
  items: string[];
}
```

Поля интерфейса:

- `payment: TPayment` — выбранный способ оплаты.
- `email: string` — электронная почта покупателя.
- `phone: string` — номер телефона покупателя.
- `address: string` — адрес доставки.
- `total: number` — общая стоимость заказа.
- `items: string[]` — массив идентификаторов товаров в заказе.

### IOrderResponse

Интерфейс `IOrderResponse` описывает ответ сервера после успешного оформления заказа.

```ts
interface IOrderResponse {
  id: string;
  total: number;
}
```

Поля интерфейса:

- `id: string` — идентификатор созданного заказа.
- `total: number` — общая стоимость заказа.

## Модели данных

В приложении используются три класса моделей данных. Каждый класс имеет свою зону ответственности и хранит определённую часть состояния приложения:

- `Catalog` — хранит товары, доступные в магазине, и товар, выбранный для подробного просмотра.
- `Cart` — хранит товары, выбранные пользователем для покупки.
- `Buyer` — хранит и проверяет данные покупателя, необходимые для оформления заказа.

### Catalog

Класс `Catalog` отвечает за хранение и управление товарами, доступными в интернет-магазине. Также он хранит товар, выбранный в данный момент для подробного просмотра.

#### Конструктор

Конструктор класса не принимает параметров.

#### Поля

- `items: IProduct[]` — хранит массив всех товаров, полученных с сервера.
- `selectedProduct: IProduct | null` — хранит товар, выбранный для подробного просмотра. Если товар не выбран, значение равно `null`.

#### Методы

- `setItems(items: IProduct[]): void` — сохраняет массив товаров, переданный в качестве параметра.
- `getItems(): IProduct[]` — возвращает массив всех товаров, хранящихся в каталоге.
- `getItem(id: string): IProduct | undefined` — возвращает товар по его уникальному `id`.
- `setSelectedProduct(product: IProduct): void` — сохраняет товар, выбранный для подробного просмотра.
- `getSelectedProduct(): IProduct | null` — возвращает товар, выбранный в данный момент для подробного просмотра.

---

### Cart

Класс `Cart` отвечает за хранение и управление товарами, выбранными пользователем для покупки.

#### Конструктор

Конструктор класса не принимает параметров.

#### Поля

- `items: IProduct[]` — хранит массив товаров, добавленных в корзину.

#### Методы

- `getItems(): IProduct[]` — возвращает все товары, находящиеся в корзине.
- `addItem(item: IProduct): void` — добавляет переданный в качестве параметра товар в корзину.
- `removeItem(id: string): void` — удаляет товар из корзины по его уникальному `id`.
- `clear(): void` — удаляет все товары из корзины.
- `getTotal(): number` — возвращает общую стоимость всех товаров, находящихся в корзине.
- `getCount(): number` — возвращает количество товаров в корзине.
- `hasItem(id: string): boolean` — проверяет, находится ли товар с указанным `id` в корзине.

---

### Buyer

Класс `Buyer` отвечает за хранение, обновление, очистку и валидацию данных покупателя, необходимых для оформления заказа.

Данные покупателя включают выбранный способ оплаты, адрес доставки, электронную почту и номер телефона.

#### Конструктор

Конструктор класса не принимает параметров.

#### Поля

- `payment: TPayment` — хранит выбранный способ оплаты. До выбора способа оплаты значение равно пустой строке `''`.
- `address: string` — хранит адрес доставки покупателя.
- `email: string` — хранит электронную почту покупателя.
- `phone: string` — хранит номер телефона покупателя.

#### Методы

- `setData(data: Partial<IBuyer>): void` — обновляет данные покупателя. Метод принимает частичный объект, что позволяет обновить одно поле, не удаляя значения, уже сохранённые в остальных полях.
- `getData(): IBuyer` — возвращает сохранённые данные покупателя.
- `clear(): void` — очищает все данные покупателя и возвращает их к первоначальным значениям.
- `validate(): Partial<Record<keyof IBuyer, string>>` — проверяет данные покупателя и возвращает объект с сообщениями об ошибках валидации. Если поле заполнено корректно, соответствующее свойство отсутствует в возвращаемом объекте.

Метод валидации проверяет каждое поле, необходимое для оформления заказа. Поле считается валидным, если оно не пустое. Для полей с отсутствующими или некорректными данными возвращаемый объект содержит соответствующее сообщение об ошибке.

Например:

```ts
{
  payment: 'Выберите способ оплаты',
  email: 'Укажите электронную почту'
}
```

Если поля `phone` и `address` заполнены корректно, они не включаются в объект с ошибками.

## Ответственность моделей данных

Ответственность моделей данных разделена следующим образом:

- `Catalog` управляет полным списком товаров и товаром, выбранным для подробного просмотра.
- `Cart` управляет товарами, выбранными для покупки, и предоставляет информацию об их количестве и общей стоимости.
- `Buyer` управляет данными покупателя и проверяет их перед отправкой заказа на сервер.

Такое разделение позволяет организовать данные приложения и предотвращает ситуацию, при которой компоненты интерфейса напрямую отвечают за хранение или изменение состояния приложения.

## Коммуникационный слой

Для взаимодействия приложения с сервером используется класс `KioskApi`.

Класс не выполняет HTTP-запросы самостоятельно, а использует экземпляр класса `Api`, переданный через конструктор. Таким образом, `KioskApi` отвечает только за работу с эндпоинтами конкретного приложения.

### KioskApi

#### Конструктор

`constructor(api: IApi)`

Принимает объект, реализующий интерфейс `IApi`, и сохраняет его для выполнения запросов к серверу.

#### Методы

- `getProducts(): Promise<IProductsResponse>` — выполняет GET-запрос на эндпоинт `/product/` и возвращает объект с массивом товаров.
- `postOrder(order: IOrder): Promise<IOrderResponse>` — отправляет данные заказа POST-запросом на эндпоинт `/order/` и возвращает данные созданного заказа.
