# Web-Larёk — Спринт 8

Учебный проект интернет-магазина «Web-Larёk». На этапе Спринта 8 подготовлена основа приложения: типы данных, модели каталога, корзины и покупателя, а также слой взаимодействия с API. Модели протестированы отдельно, получение каталога с сервера выполняется через `KioskApi`.

## Стек

- TypeScript
- Vite
- HTML
- SCSS
- REST API
- npm

## Установка и запуск

Для работы необходимы Node.js и npm.

```bash
npm install
```

Запуск проекта в режиме разработки:

```bash
npm run dev
```

Проверка TypeScript и сборка проекта:

```bash
npm run build
```

Локальный просмотр собранной версии:

```bash
npm run preview
```

## Архитектура

Приложение строится по архитектурному паттерну MVP — Model, View, Presenter.

- **Model** хранит данные и реализует бизнес-логику. В текущей части проекта это классы `Catalog`, `Cart` и `Buyer`.
- **View** отвечает за отображение данных и взаимодействие пользователя с интерфейсом. Компоненты представления не хранят состояние приложения напрямую.
- **Presenter** связывает модели и представления: обрабатывает действия пользователя, вызывает методы моделей и передаёт изменившиеся данные интерфейсу. Связывание слоёв выполняется в точке входа приложения.

Дополнительно выделен коммуникационный слой. `Api` выполняет HTTP-запросы, а `KioskApi` описывает запросы, относящиеся именно к Web-Larёк. Модели не обращаются к серверу самостоятельно.

```text
REST API
   ↓
Api → KioskApi
          ↓
Presenter ↔ Model
    ↕
   View
```

На Спринте 8 реализованы и проверены модели и коммуникационный слой. Компоненты отображения и полная событийная связь слоёв добавляются на следующем этапе проекта.

## Данные и типы

Основные типы приложения описывают товар, покупателя и данные, которыми приложение обменивается с сервером.

### `TPayment`

Тип доступных способов оплаты. Пустая строка означает, что способ оплаты ещё не выбран.

```ts
type TPayment = "card" | "cash" | "";
```

### `IProduct`

Описывает товар, доступный в интернет-магазине.

```ts
interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}
```

- `id: string` — уникальный идентификатор товара.
- `description: string` — описание товара.
- `image: string` — путь к изображению товара.
- `title: string` — название товара.
- `category: string` — категория товара.
- `price: number | null` — цена товара; `null`, если товар нельзя купить.

### `IBuyer`

Описывает данные покупателя, необходимые для оформления заказа.

```ts
interface IBuyer {
  payment: TPayment;
  email: string;
  phone: string;
  address: string;
}
```

- `payment: TPayment` — выбранный способ оплаты.
- `email: string` — электронная почта покупателя.
- `phone: string` — номер телефона покупателя.
- `address: string` — адрес доставки.

### `IProductsResponse`

Описывает ответ сервера при получении каталога товаров.

```ts
interface IProductsResponse {
  total: number;
  items: IProduct[];
}
```

- `total: number` — общее количество товаров.
- `items: IProduct[]` — массив полученных товаров.

### `IOrder`

Описывает заказ, отправляемый на сервер.

```ts
interface IOrder {
  payment: TPayment;
  email: string;
  phone: string;
  address: string;
  total: number;
  items: string[];
}
```

- `payment: TPayment` — выбранный способ оплаты.
- `email: string` — электронная почта покупателя.
- `phone: string` — номер телефона покупателя.
- `address: string` — адрес доставки.
- `total: number` — общая стоимость заказа.
- `items: string[]` — идентификаторы товаров в заказе.

### `IOrderResponse`

Описывает ответ сервера после успешного оформления заказа.

```ts
interface IOrderResponse {
  id: string;
  total: number;
}
```

- `id: string` — идентификатор созданного заказа.
- `total: number` — общая стоимость заказа.

### `IApi`

Описывает объект, через который `KioskApi` выполняет запросы. Благодаря интерфейсу прикладной API зависит не от конкретной реализации, а от доступных методов `get` и `post`.

## Модели данных

Каждая модель отвечает только за свою часть состояния:

- `Catalog` — каталог и выбранный товар;
- `Cart` — товары, выбранные для покупки;
- `Buyer` — данные покупателя и их проверка.

### `Catalog`

Хранит полученный каталог и товар, открытый для подробного просмотра.

#### Конструктор

```ts
constructor();
```

Параметров не принимает. Создаёт пустой каталог без выбранного товара.

#### Поля

- `items: IProduct[]` — массив товаров.
- `selectedProduct: IProduct | null` — выбранный товар либо `null`.

#### Методы

- `setItems(items: IProduct[]): void` — сохраняет переданный массив товаров.
- `getItems(): IProduct[]` — возвращает все товары каталога.
- `getItem(id: string): IProduct | undefined` — находит товар по идентификатору.
- `setSelectedProduct(product: IProduct): void` — сохраняет выбранный товар.
- `getSelectedProduct(): IProduct | null` — возвращает выбранный товар.

### `Cart`

Хранит товары, которые пользователь добавил в корзину, и предоставляет вычисляемые данные о корзине.

#### Конструктор

```ts
constructor();
```

Параметров не принимает. Создаёт пустую корзину.

#### Поля

- `items: IProduct[]` — товары в корзине.

#### Методы

- `getItems(): IProduct[]` — возвращает товары корзины.
- `addItem(item: IProduct): void` — добавляет товар.
- `removeItem(id: string): void` — удаляет товар по идентификатору.
- `clear(): void` — очищает корзину.
- `getTotal(): number` — возвращает общую стоимость товаров.
- `getCount(): number` — возвращает количество товаров.
- `hasItem(id: string): boolean` — проверяет наличие товара по идентификатору.

### `Buyer`

Хранит, частично обновляет, очищает и проверяет данные покупателя.

#### Конструктор

```ts
constructor();
```

Параметров не принимает. Создаёт объект с пустыми значениями полей.

#### Поля

- `payment: TPayment` — способ оплаты; начальное значение `''`.
- `address: string` — адрес доставки.
- `email: string` — электронная почта.
- `phone: string` — номер телефона.

#### Методы

- `setData(data: Partial<IBuyer>): void` — обновляет переданные поля, сохраняя остальные значения.
- `getData(): IBuyer` — возвращает сохранённые данные покупателя.
- `clear(): void` — возвращает все поля к начальным значениям.
- `validate(): Partial<Record<keyof IBuyer, string>>` — возвращает объект с сообщениями об ошибках для незаполненных полей.

Пример результата валидации:

```ts
{
  payment: 'Выберите способ оплаты',
  email: 'Укажите электронную почту'
}
```

Метод проверяет заполненность обязательных полей. Проверка формата электронной почты или номера телефона в текущей реализации не выполняется.

## Коммуникационный слой

### `Api`

Базовый класс стартового проекта для выполнения HTTP-запросов. Он отвечает за общие детали работы с сервером и не содержит логики Web-Larёк.

#### Конструктор

```ts
constructor(baseUrl: string, options: RequestInit = {})
```

- `baseUrl: string` — базовый адрес API.
- `options: RequestInit` — дополнительные параметры запросов.

#### Поля

- `baseUrl: string` — базовый адрес сервера, доступный только для чтения.
- `options: RequestInit` — общие настройки запросов.

#### Методы

- `get(uri: string)` — выполняет GET-запрос.
- `post(uri: string, data: object, method = 'POST')` — отправляет данные методом POST, PUT или DELETE.
- `handleResponse(response: Response)` — обрабатывает ответ сервера и отклоняет Promise при ошибочном ответе.

### `KioskApi`

Прикладной коммуникационный класс. Использует переданный объект `IApi` и знает эндпоинты Web-Larёк, но не хранит состояние каталога, корзины или покупателя.

#### Конструктор

```ts
constructor(api: IApi)
```

- `api: IApi` — объект для выполнения HTTP-запросов; сохраняется как приватное поле.

#### Методы

- `getProducts(): Promise<IProductsResponse>` — выполняет GET-запрос на `/product/` и возвращает каталог.
- `postOrder(order: IOrder): Promise<IOrderResponse>` — отправляет заказ POST-запросом на `/order/` и возвращает результат его создания.

## Разделение ответственности

- `Catalog`, `Cart` и `Buyer` хранят и обрабатывают данные своих предметных областей.
- `Api` решает общую задачу выполнения HTTP-запросов.
- `KioskApi` связывает методы API с эндпоинтами приложения.
- Точка входа создаёт экземпляры классов, получает товары через `KioskApi` и передаёт `data.items` в `Catalog`.
- Интерфейс не должен напрямую хранить или изменять состояние приложения: он работает с моделями через их публичные методы.

Такое разделение уменьшает связанность кода: изменение способа отображения не требует переписывать модели, а изменение сетевого слоя не переносит HTTP-логику в классы данных.
